# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. It is the session-wide part: the constraints every session needs, the commands, and a router into the notes where the reasoning lives. **It states no counts** (commits, tests, files, sizes, lines): wherever it needs one, it gives the command that measures it, because every number written here has gone stale, usually within days. A change in the gap that no new loop explains is the signal worth reading.

### Encoding and line endings

- **Never edit files with PowerShell `Get-Content` / `Set-Content`.** Windows PowerShell 5.1 decodes with the ANSI codepage, so a read-modify-write round-trip turns every UTF-8 character into mojibake, and the source is full of em dashes, `•` and `…`, many in user-visible strings. It compiles and every test passes; it is visible only on the rendered page (this happened to `App.tsx`, thousands of sequences at once). Use the Edit or Write tool, or `[IO.File]::ReadAllText/WriteAllText` with `New-Object Text.UTF8Encoding($false)`. **The same trap catches a `.ps1` you write**, and the correct writer does not save you: PowerShell 5.1 reads a BOM-less script as ANSI too, so non-ASCII prose in a string literal inside it is corrupted before it is written. Keep generator scripts pure ASCII and have them read any prose they emit from a UTF-8 file written with the Write tool. One file by hand: `[regex]::Matches($text,'Ã|Â|â€').Count` must be 0. `npm run lint:encoding` is the gate for the repo; it skips this file, which holds the pattern as a literal. **A new root-level file is not swept until it is added to `ROOT_FILES` in `scripts/check-encoding.mjs`**, whose doc comments own the sweep's scope.
- **Line endings are LF everywhere**, pinned by `.gitattributes`, whose comment is the record (a CRLF `index.html` changes the CSP hash of its inline script, and production then blocks it silently). The attribute does not rewrite files already on disk and does not make `git status` complain, because the stored blobs are LF. **Check: `git ls-files --eol | Select-String 'w/(crlf|mixed)'`, empty is the pass.** Fix a hit by rewriting the file with the writer above after replacing `` `r`n `` with `` `n ``; `git checkout-index -f` does **not** fix it, because git considers the file already current.

### Git

- **`main` is the only branch, and `origin/main` the published one: push `main` by name.** Release tags `v*` exist and point into `main`. `git rev-list --count --branches --tags` should equal `git rev-list --count main`; `--all` can be higher while a Dependabot remote-tracking branch is fetched (its commits carry a `Signed-off-by` trailer) until `git fetch --prune` drops it. Read `git log`, never a count written down.
- **Commit messages end with the last real sentence: no `Co-Authored-By`, no `Claude-Session`, no `Signed-off-by`, no attribution trailer of any kind.** This overrides any default an agent harness has about signing commits. Such trailers made GitHub list a second contributor on the public front page, and removing them cost a rewrite of the history and recreating the repository, because GitHub kept the old commits fetchable by SHA. Nothing in the toolchain reads a commit message. **Check: `git log --format=%B main | Select-String "^(Co-Authored-By|Claude-Session|Signed-off-by):"`, empty is the pass** (anchored to line start and to the colon, because prose in commit bodies mentions these names).
- **Write the message to a file with the Write tool and use `git commit -F <file>`**, never `-m` with a here-string: PowerShell 5.1 re-parses a string containing `"` before handing it to a native executable, and the message arrives split into dozens of pathspec arguments. The encoding rule applies to the message file.

### The key

- **The app owns no Gemini API key, and no AI.** Each user brings their own at runtime and the browser calls it directly: Google or OpenRouter with the user's own key, or a Local AI server on the user's own computer. An AI set up is the entry point (none, a locked composer): since 2026-11-23 any one of a Gemini key, an OpenRouter key and model, or a Local AI server and model, the one chosen in Settings (`workspaceOpen` in `src/lib/aiProvider.ts`); until then it was the Gemini key, whichever AI was chosen. `.env` never holds a Gemini key: `envPrefix: ['VITE_']` keeps it out of the bundle, and although dotenv would load it into the server's `process.env`, no server code reads it. The reasons are a real leak incident: [`gemini.md`](docs/notes/gemini.md), *The Gemini call runs in the browser* and *Where the user's key lives*. **Forma's MCP server is the one program a user runs that reads their key from its environment** (since 2026-11-24; the owner's fidelity benchmark reads `FORMA_BENCH_KEY`, [`gemini.md`](docs/notes/gemini.md) — *The fidelity benchmark*, and `boundaries.test.ts`'s `KNOWN_OUTSIDE` lists each read of a key variable outside `src/mcp`): the user's own, set in the host's entry for it, under Forma's own names (`FORMA_GEMINI_KEY`, `FORMA_OPENROUTER_KEY`), read only in `src/mcp/stdio.ts` and handed to `aiSettings.ts`, never by dotenv, never `GEMINI_API_KEY` (deleted from its environment before the Gemini SDK loads), and `geminiService.ts` keeps no environment read. The site's statements about the key (`sessionStorage`, never on disk in readable form) are about the site; where the server's key lives instead, readable in the host's configuration file or the user's environment, is [`mcp.md`](docs/notes/mcp.md) — *The AI tools make and revise a report with the user's own AI*.

## Project

**Forma**: an AI-powered DevExpress report designer. The user attaches an image, a PDF or a `.repx` (or describes a report in words); the AI they chose (Gemini by default, or Local AI through Ollama or LM Studio, or OpenRouter's free models, through `src/services/compatClient.ts`) works with OCR and Forma's own model on each request, and the result is `repxContent`, valid DevExpress `XtraReportsLayoutSerializer` XML that downloads as a `.repx`. Forma reads the Mockup's layout and the markdown Spec off that REPX (`src/lib/repxViews.ts`).

Stack: React 19, Vite 8 (Rolldown), Tailwind v4, TypeScript, Express (the dev server, and the self-hosted `npm start` path), Firebase Auth and Firestore, Firebase Hosting (the deployed site, served statically), Gemini via `@google/genai`. OCR runs in the browser: PaddleOCR (PP-OCRv5) for English where the deploy fetched it, Tesseract.js otherwise. Forma's own model drafts for the AI and stands in for it when it fails; there is no mode without an AI. Entry points: `server.ts`; `src/main.tsx`, which draws `src/PublicSite.tsx` (every public page) or lazy-loads `src/App.tsx` (the workspace, on `/workspace`); `src/services/geminiService.ts`; and, outside the site, `src/mcp/run.mjs`, Forma's MCP server, which a user's AI host runs from a clone.

### Code map

Verified against `main` on 2026-11-11. Symbols are stable, line numbers are not: grep for the identifier.

- **Build**: `vite build`, whose `closeBundle` hook (`vite.config.ts`) starts a second Vite in SSR mode with its own `cacheDir`, renders every public route from `src/prerender.tsx` into its own HTML (plus `share.html` and `404.html`, not hydrated: `createRoot` replaces it), then esbuild bundles `server.ts`.

- **Generation**: `runGeneration` (in `App.tsx`, the reply and the bench) calls `generateReport` in `src/lib/generationCore.ts`, the one core the workspace (`readRequest`, `generateReport`) and `batchRun.ts` (`makeReport`) call and the MCP server's AI tools call in Node, with everything the browser owns handed in. Runaway, unfinished, 503 and quota answers are retried within one request budget (`REQUEST_BUDGET`), then the next model.
- **After the answer**: `repairRepx` (`src/lib/repairChain.ts`, the one place the order lives: `REPAIR_ORDER`), on a picture run `fitGeometry` (`sourceAgreement.ts`, moving bands toward where the page printed them), then `auditRepx` against OCR's evidence, `readCoverage` with one re-ask when too much of what Forma read is missing, and the print check (`printCheck`, against the page's own records from `pageRows`). The key: `sessionStorage`, with an optional AES-GCM copy in Firestore. Kept reports, their style and the corrections ledger stay on the device (`learningLoop.ts`, `memory.ts`, `forma-library`).
- **`server.ts`**: development is Express plus Vite in middleware mode on loopback; `npm start` serves `dist/` statically. The live site is Firebase Hosting and never runs it.
- **The MCP server** (`src/mcp`, Node only, since 2026-11-24; not built into `dist/`, never deployed): a host runs `node <clone>/src/mcp/run.mjs`, which registers tsx and loads `stdio.ts`, whose first act is `installStdoutGuard`; then `serveStdio` with `createFormaServer` (`formaServer.ts`), which registers `TOOL_LIST`'s tools (`toolList.ts`), each through `defineTool` (`toolShape.ts`): `forma_status` (`statusTool.ts`) and the report tools (`reportTools.ts`), which read and write only through `reportFile.ts`, `paths.ts` and the folders `roots.ts` works out, and run the web app's own `auditRepx`, `reportOutline`, `repairRepx`, `applyEdits` and `draftPdf` in a worker thread with a memory bound and a deadline (`workerPool.ts` starts `worker.mjs`, which runs `pipeline.ts`); and since 2026-11-24 the two AI tools (`aiTools.ts`), `generate_report` (`makeReport` with Node's parts, `nodeGeneration.ts`) and `revise_report` (the chat's own path, stateless), gated by `aiSettings.ts` on the AI set up in the entry's environment and run one at a time (`generator.ts` `oneAtATime`) in a worker thread of their own (`genWorker.mjs`, which runs `genJobs.ts`), every result and log line through `lib/keyRedact.ts`.

## Where the reasoning lives

The reasoning behind this codebase is in the notes, the proposals, two tool READMEs and doc comments, **not here, and none of it is loaded automatically.** Open the section that owns what you are touching before you change it: each records the incidents that produced the current shape, and skipping it is how something fixed once gets broken again. **Open a note at the heading, not at the top**: the large notes cost more context end to end than a whole session should spend on one question, so `grep -n "<heading>" docs/notes/<note>.md` and read from there. Do not "fix" that by trimming the notes; length is not the defect.

**The lookup rule.** For a file or a symbol: `git grep -n <basename> -- docs/notes docs/proposals docs/skills tools/*/README.md ':!docs/notes/testing.md'` (testing.md names nearly every module, because it lists every test file). **Where the doc comment is the note**: `src/server/*`, `src/fonts/README.md`, `scripts/check-*.mjs`, `scripts/deploy.mjs`, `tsconfig.json`, `vite.config.ts`, `vitest.config.ts`, `package.json`'s `comment:*` fields, `.gitattributes`, `.gitignore`, `.env.example`. A grep of `docs/` finds none of those: `git grep -n "Content-Security-Policy"` does.

**New reasoning goes in the note that owns the area, never here.** This file grows only for what every session needs. **A cited heading must stay plain** (no emphasis inside it, 3 to 14 words, cited in single emphasis on the same line as its relative link), or `npm run lint:links` stops checking it; never refer to a row of the table below by position.

```powershell
npm run mcp          # node src/mcp/run.mjs -- Forma's MCP server on stdio, for development from the clone; never a host's command (npm's banner goes to stdout, which the protocol forbids, and a host starts in the user's project, whose own package.json npm would run): a host runs node <clone>/src/mcp/run.mjs
npm run clean        # removes dist/
npm run preview      # vite preview against dist/
```

**These seven commands are the whole of what a machine checks locally.** Everything else in this document is verified by reading or by looking at the rendered page:

```powershell
npm run lint                                            # tsc --noEmit; the baseline is clean, so any output is yours
npx tsc --noEmit --noUnusedLocals --noUnusedParameters  # dead code; also clean, so treat any hit as newly introduced
npm run lint:encoding                                   # the mojibake sweep; exits 1 with the offending paths
npm run lint:links                                      # every relative link and cited heading in the docs still resolves
npm test                                                # the unit suite
npm run test:rules                                      # firestore.rules, via the emulator (needs Java)
npm run build; npm run check:size                       # artifact budgets; must follow a build
```

- **CI (`.github/workflows/checks.yml`) runs all seven plus what no local check does**: `npm ci` (which fails when `package.json` and the lockfile disagree), `node --check` on the hook and the run-forma driver, and `scripts/check-dist.mjs` on the built pages and the started `npm start` server (`deploy.mjs` runs the pages half as well). One job runs everything but the rules suite, on Node 24.15.0 and the newest 24, ending with `npm run build`, `npm run check:size` and that last step; the rules suite is its own job, because it needs a JVM. Its unit step is `npm run test:coverage`, the same suite with the summary in the log. CI gates nothing locally: run the checks before committing, and read `gh run list` and the run after pushing.
- **The budgets in `check:size` are tight on purpose.** Read the doc comment of `scripts/check-bundle-size.mjs` before raising one; growth in a budgeted chunk is paid for by moving code into a lazy module, not by raising the number.
- **Coverage is deliberately scoped** to `src/lib`, `src/services`, `src/server` and `src/mcp` (the last since 2026-11-24, owner decision OD8 of the MCP work: its path and stdout rules are security code, so they get a floor; only its entry, `src/mcp/stdio.ts` and the launcher `src/mcp/run.mjs`, is excluded, because it runs in a spawned process coverage does not follow, with the two worker threads' launchers, `src/mcp/worker.mjs` and `src/mcp/genWorker.mjs`, which coverage does not follow either (the work each runs is measured in the tests' own thread), and the tests' own file system and client, `src/mcp/testFs.ts` and `src/mcp/testClient.ts`, which are test code): do not widen the include further; raise the number by shrinking `App.tsx` ([`testing.md`](docs/notes/testing.md), *What `npm run test:coverage` measures*).

### Owner-only operations

- **Deploying is the owner's, and it publishes.** `node scripts/deploy.mjs` is the one way: it refuses unless the tree is `main` exactly as pushed, runs the seven checks above, builds, holds the built pages to `firebase.json`'s policy (`check-dist.mjs`, without `--server`), deploys hosting, `firestore.rules` and `firestore.indexes.json` together, runs `npm run smoke` against the live sites expecting that commit, and tags and releases it. `--preview` puts the build on a 7-day preview channel and needs only a clean tree (any branch, no version or tag check, the live site and rules left alone); `--dry-run` stops before deploying. **It is deliberately not an npm script**, because `npm run *` is allowlisted; `node` and `npx firebase deploy` are not. Run it only when the owner says to deploy. `.github/workflows/live.yml` checks the live site every three hours, read-only. Rolling back is in [`docs/deploying.md`](docs/deploying.md) — *Firebase Hosting*.
- **Every deploy of `main` is a numbered release.** To ship new work, raise `package.json`'s version, the newest entry of `src/lib/releases.ts` and the Docs page's MCP clone line (`--branch v<version>`, since 1.7.0) in one commit (`npm version <x.y.z> --no-git-tag-version` keeps the lockfile in step); the script stops before building if the tag already names another commit.
- **Also the owner's to run, never a session's**: `node scripts/github-setup.mjs` (repository settings, labels, milestones); `npx tsx scripts/model/pull-learning.ts`, `scripts/model/learn-week.ts`, `scripts/backup.mjs` and `scripts/admin/*`, which need a credential that can read every account and stays on the owner's own PC, outside the repository (*Learning from use* and *Answering a data request* in [`persistence.md`](docs/notes/persistence.md)). Shipping a retrained model is the owner's decision too, and only a candidate that `scripts/model/gate.ts` passes (`gateModels`, which the weekly job runs as well) may replace `assets/model/formaModel.json`.

### Running things

- **Never run bare `vite dev`.** The dev server is `server.ts`, with Vite in middleware mode inside it.
- **Long-lived and visible processes belong to the user.** `npm run dev` runs in the owner's own terminal on 3000; to see its output, ask for `npm run dev:log` and read `dev-server.log`, which exists only while that script runs, is truncated on each run and starts with a `=== npm run dev:log - <ISO> ===` header to check. Take a port yourself only for a short, self-contained check, 3001 by preference, and free it. **`RepxDesigner.exe --serve` is the user's to start unless they ask you to**: a process paints on the desktop of the session that created it. On the shared server an agent shell ran in a session nobody was watching, so the designer opened unseen and reported success; here the agent shell and the desktop are both session 1 (2026-11-21), so it opens on the owner's screen.
- **To run the app, follow [`.claude/skills/run-forma/SKILL.md`](.claude/skills/run-forma/SKILL.md)**: the mock server on 3001 and a Chrome of its own through Playwright MCP, registered at user scope (`claude mcp get playwright` prints its command; no `--isolated`, by the owner's choice). **The Claude in Chrome extension is allowed** since 2026-11-21: the ban of 2026-11-12 was a company policy for the shared server Forma was built on, and the owner lifted it for this personal machine. Never a headless browser started from the shell unless the owner asks for one, and never a debugging port: any process on the machine can drive the browser through it. Keep `drive.mjs` pure ASCII: `lint:encoding` catches it once corrupted, not a correctly encoded non-ASCII character, so that rule is still manual.
- **A change to `vite.config.ts`, or to any module under `src/lib` it imports (read its import block; adding a release is such a change), restarts Vite inside a running dev server, and a tab on it can then load blank with nothing in the console.** Restart your own server and reload; the owner's on 3000 needs the same restart, which is theirs to make, so tell them. If the console says `jsxDEV is not a function`, stop the server, delete `node_modules/.vite/deps` and start it again. **With two dev servers running (3000 and 3001 share that cache), stop both first and start them one at a time**: re-optimising both at once into one folder loads two copies of React (`Cannot read properties of null (reading 'useSyncExternalStore')`) and leaves `deps_temp_*` folders behind.
- **Registering Forma's MCP server in a host is the owner's step** (2026-11-24, the MCP design audit's DOC-12): `claude mcp add` writes the owner's `~/.claude.json`, so a session does it only when the owner says so, in local scope, and never with a key unless the owner says so. No tool of Forma's goes into `.claude/settings.json` unless the owner says so, and never one that spends quota. `npm run mcp` is allowed through `npm run *` and waits on stdin like any stdio server: run it only inside a short check of your own that ends it, as `src/mcp/stdio.test.ts` does. [`mcp.md`](docs/notes/mcp.md) — *What comes next, and whose step each is*.
- **`npm start` needs `npm run build` first and must run from the repo root** (it serves `process.cwd()/dist`; the bundle bakes in `NODE_ENV=production`).
- **`.env` holds no Gemini key.** `.env.example` documents the variables there are (`VITE_FORMA_MOCK`, `VITE_FIREBASE_EMULATORS`, `PORT`, `HOST`, `HTTPS`), and says the MCP server reads none of it (it loads no `.env`; `FORMA_MCP_ROOTS` and the AI's `FORMA_*` variables go in its host's entry); `.env*` is gitignored except that file. `APP_URL` was removed as read by nothing: do not restore it or read it.
- **Leave `vite.config.ts`'s HMR block** (*"Do not modify"*, file watching gated on `DISABLE_HMR`) **and `watch: { ignored: ['**/tools/**'] }` alone**: chokidar throws `EBUSY` on MSBuild's locked `bin/`/`obj/` files and takes the dev server down.
- `src/App.tsx` is several thousand lines and keeps growing: grep for a symbol, never trust a line number in this file or a note.

### Tests in practice

- **One file: `npx vitest run src/lib/repx.test.ts`; one case: add `-t "<name>"`.** Narrowing buys clarity; how much time it saves depends on the cache, and [`testing.md`](docs/notes/testing.md), *Running one file, and what that does not buy you*, says why no timing is written down.
- **If every jsdom file dies at once with `[vitest-pool-runner]: Timeout waiting for worker to respond`, nothing is broken and re-running will not help**: jsdom's cold load exceeds Vitest's worker-start timeout. Warm it in a process nothing is timing, `node -e "import('jsdom')"`, then run the suite. A timeout in only the first case of a file is a lazy loader paying its cold import inside that test's budget, not a slow test. Both are in [`testing.md`](docs/notes/testing.md), *A cold cache can look exactly like a broken install*.
- **The rules suite runs under its own config**: `firebase emulators:exec --only firestore "vitest run --config vitest.rules.config.ts"`. A single rules case needs a space-free regex to survive PowerShell's re-parsing ([`testing.md`](docs/notes/testing.md), *Running a single rules case: use a space-free regex*).

### Repository settings

- **`.claude/settings.json` is the committed permission allowlist**: `npm run *`, `npm test`, `npm ls *`, `npx tsc *`, `npx vitest *`, `New-Item *`, `Get-Process *`, which covers every check above and every `npm run` script. `npm test` and `npm start` are not `npm run test` / `npm run start`, so `npm test` has its own entry and `npm start` (a long-lived server) prompts, as the env-prefixed mock-server line may. Personal permissions go in `settings.local.json`, which is gitignored.
- **The pre-commit hook is opt-in**: `git config core.hooksPath .githooks` once per clone, `--no-verify` to bypass one commit. `.githooks/pre-commit.mjs` blocks files over 1 MB, backup and archive extensions, log files, copy-looking names, OS droppings, an assignment of a real-looking API key (JSON-shaped and under the `FORMA_*KEY` and OpenRouter names too) and a key, token or password written into an MCP host config (`.mcp.json`, `mcp.json`, `claude_desktop_config.json`, `mcp_config.json`, `.gemini/settings.json`), reading the staged content, renames included, then runs the project hierarchy check (the Git section above says how to answer it). The logic is Node because the shared server's Git was MinGit, with no MSYS userland; this machine has full Git for Windows (`C:\Program Files\Git`, with `grep` and `wc` under `usr\bin`), and Node stays because CI and any clone run it the same way; if you rewrite it, verify it with a commit that should fail.
- **`.gitignore`'s credential patterns are a backstop, not permission**: `key.txt`, `*.key`, `*apikey*`, `*api-key*`, `secrets.json`, Firebase service-account keys (`*firebase-adminsdk*.json`, `service-account*.json`) and the backup's `forma-firestore-*.ndjson`. A Gemini key belongs in the app's Settings (`sessionStorage`); a service-account key belongs on the owner's own PC, outside the repository.
- **`.firebaserc` stays tracked**: it names the deploy target and holds no credential, and ignoring it is how a clone deploys to whichever project the CLI last selected. `.firebase/` is ignored.

## Structure conventions

These hold everywhere today. The `src/server` and `src/mcp` rules are held by `src/mcp/boundaries.test.ts`; nothing in the toolchain enforces the rest. `CONTRIBUTING.md`'s *Structure* section is the public copy.

- **`src/lib` is browser code; `src/server` is not.** `server.ts` imports `securityHeaders`, `appRoutes`, `bindHost` and `staticCache` from `src/server/`; no browser code may import from it (tests may), and `src/mcp/boundaries.test.ts` fails if anything but `server.ts` and tests does. Those modules stay under `src/` because `vitest.config.ts` includes only `src/**/*.test.{ts,tsx}`: moving them out silently drops their tests unless the include widens in the same commit.
- **`src/mcp` is Node only, as `src/server` is** (since 2026-11-24): Forma's MCP server, entered at `src/mcp/stdio.ts` through the launcher a host runs, `src/mcp/run.mjs`. No browser code imports it (tests may), it reaches no browser-only module through any import its walk can follow (a lazy import built at run time is refused, since none can be followed), nothing it reaches writes to stdout around the guard, only it and `src/server` import a Node built-in, it never imports the v1 SDK `@modelcontextprotocol/sdk`, it opens no port, and within it only the entry touches the environment. `src/mcp/boundaries.test.ts` holds those with regular expressions over the sources, which find the shapes this codebase writes and are not a parser (its doc comment names what they cannot see), and `src/server`'s half with them (nothing but `server.ts` imports it, tests aside). An MCP tool goes in `src/mcp`, through `defineTool` (`toolShape.ts`); the pipeline it calls stays in `src/lib`.
- **Naming under `src/`: `PascalCase.tsx` for React components, `camelCase.ts` for everything else**, with one exception, `src/vite-env.d.ts` (Vite's conventional name). Not every `.tsx` is a component: entry points, modules exporting collections (`icons.tsx`, `sections.tsx`, `infoPages.tsx`, `faqs.tsx`, `publicPages.tsx`, `docsCorpus.tsx`) and colocated `*.test.tsx` files are not; do not rename them. `scripts/` uses kebab-case for some entry scripts and root configs follow their tools' names. To count, `git ls-files | Where-Object { $_ -like '*.tsx' }` (a pathspec like `'src/**/*.tsx'` drops the files directly in `src/`).
- **Tests are colocated** (`*.test.ts[x]` beside the module); **`tests/` at the root is only for the emulator**, which is what keeps `npm test` from starting a JVM. A module can have a file in both.
- **No barrel files**, and **no `@` path alias**: every import is relative. An alias has to be declared in `tsconfig.json`, `vite.config.ts` and `vitest.config.ts` at once and actually used, or not at all.
- **Where new code goes**: a pure helper in `src/lib`, a server helper in `src/server`, a component in `src/components` (`landing/` for a landing-page figure), an MCP tool in `src/mcp` (listed in `toolList.ts`, made with `defineTool`, the pipeline it runs left in `src/lib`). **A new top-level directory needs a stated reason**; the current set is what `git ls-tree --name-only -d HEAD` prints.
- **`docs/` holds the project's documentation prose**, apart from the root-level community files and the READMEs that live beside the code they describe (`tools/`, `src/fonts/`, `assets/pdf-fonts/`). `PRD.md` and `notes/` are current and maintained against the code; `project-structure.md` is the file layout and `deploying.md` the hosting, deploy, release and rollback reference, both moved out of `README.md` on 2026-11-21 to keep it short; `design/DESIGN.md` is the design source of truth; `proposals/` holds what has not graduated into `notes/` (when one proves out, its reasoning moves into `notes/` and the proposal goes); `skills/devexpress-repx/SKILL.md` is what Forma measured about the REPX format, written for a person or a coding assistant working on a `.repx` outside the app (`scripts/repx.ts` is its command line, and the MCP server serves it as a resource); `audit/README.md` is a dated index of the audit identifiers (`ARC-001`, `PERF-002`…) that comments across the code cite, and owns their count. **`docs/media/` is the only place a screenshot may be committed**, and its README carries the capture and recapture rules.
- **Removal sites carry a comment dating the removal**; `git log -S'<symbol>'` finds the commit. The 2026-08-28 cleanup pass is recorded in its commit messages, `git log 2ce6e56..9a8163c`.
