## Read this first

These constraints change how you work here before you touch anything:

- **There are two test suites, and between them they still cover little.** `npm test` runs Vitest under the `node` environment by default, with the files that genuinely need a DOM opting into jsdom on their own first line (see `vitest.config.ts` for why that split is load-bearing rather than tidiness). `npm run test:rules` runs against the Firestore emulator. Between them they cover the pure helpers in `src/lib`, the config-persistence allowlist, the stream scanner, the AES-GCM key vault, the two outbound calls that can hang, the three `src/server` modules and the `firebase.json` hosting headers that mirror them, `firestore.rules`, a handful of component render tests, and every public page as the build draws it (`src/prerender.test.ts`: its structure, its ids and every link, since 2026-11-08). [`docs/notes/testing.md`](docs/notes/testing.md) carries the totals, the per-file inventory and which files those are; the bullet below is why they are written down there and not here. Each was chosen because it encodes an invariant that fails *plausibly* rather than loudly. **Everything else is unenforced** — `App.tsx` is several thousand lines, and the only parts of it under test are the pieces that have been extracted out into `src/lib` and `src/components`; most of what remains has no render test at all. (It read "~4,450" here and in `testing.md` until 2026-09-06, when the answer was 4,877. A line count is the same class of number as the commit total this file refuses to keep below, and `app-shell.md` already declines to write one in the heading that owns the file — measure it when you need it.) Where this document calls something an invariant and it is not in one of those files, you check it by hand or it ships broken.

- **`npm run test:rules` needs Java** (the Firestore emulator is a JVM process). A Temurin JRE 21 is installed at `%LOCALAPPDATA%\Programs\Temurin\jdk-21.0.12+8-jre` with `JAVA_HOME` and `PATH` set at user scope — no admin was required, and nothing was installed system-wide. - **The Node floor is 20, and it is not a round-number preference.** `package.json` declares `"engines": { "node": "^20 || ^22 || >=24" }` as of `493748e` (2026-08-27) — before that there was no field at all, so npm warned about nothing and a wrong runtime arrived later as a syntax or API error from inside a dependency, which reads as a broken repository rather than a bad Node version. Note npm *warns*, it does not refuse: there is no `engine-strict`, so the declaration is a signal, not a gate. The floor is set by `vitest` (`^20 || ^22 || >=24`) and `firebase-tools` (`>=20`); `vite` alone would still accept 18. Note vitest's range is the even LTS lines *plus* `>=24`, so **Node 21 and 23 fall outside it** and ">=20" is the wrong mental model. Developed and verified on **Node 24.21.0 / npm 11.19.0** (it said 24.18.1 / 11.16.0 until 2026-10-24; `node -v; npm -v` is the current answer, and the npm one matters because 11.19 is where the `allowScripts` warning below began). `README.md` *and* `CONTRIBUTING.md` both state the same floor for contributors, so changing it is a change to **three** files — this bullet said "two" until 2026-09-01, which is how a rule about drift acquired its own.
- **`package.json` carries two npm-level decisions that read as noise or as an accident, and each has a `comment:` field beside it that owns the reasoning.** Read those before touching either. **`allowScripts`** (`52da46e`, 2026-10-24) approves the five dependencies whose install scripts npm 11.19 warns about on every install, pinned to exact versions, which is npm's default — so a bump to any of them brings the warning back *on purpose*, and the answer is to review and re-approve rather than to widen the pin. `npm install-scripts ls` reports what is still unreviewed; empty is the pass. **`overrides.qs`** is there because this project's own Express 4 range can only resolve to a vulnerable `qs`, not because of the `@google/genai` chain an earlier comment blamed. - **`tsconfig.json` enables `strict` as of 2026-08-27**, so `npm run lint` now means roughly what it looks like it means — and **the baseline is clean, so anything `tsc` prints is yours.** Two things follow that are easy to undo by accident. `@types/react` is now *declared* rather than inherited from `react-markdown`; do not remove it from `devDependencies` on the grounds that nothing imports it, because without it every `.tsx` file silently degrades to `any` while `tsc` still exits 0 — the same failure `strict` exists to prevent. - **Line endings are LF everywhere, pinned by `.gitattributes`, and that file's own comment is the record.** Added in `5dbb0c3` after 2026-09-21, when a CRLF working tree changed the SHA-256 of the inline theme script in `index.html`: `securityHeaders.test.ts` failed, and the build's `dist/index.html` no longer matched the CSP the server sends, so the script would have been blocked in production and the flash of light theme it prevents would have come back, throwing nothing. ## Project

**Forma** — an AI-powered DevExpress report designer. The user uploads an image, PDF, or `.repx` file; the AI the user chose (Gemini by default, or Local AI or OpenRouter) analyzes it, helped by OCR and Forma's own model (`src/lib/formaTeam.ts`), and returns `repxContent` — valid DevExpress `XtraReportsLayoutSerializer` XML that downloads as a `.repx` file — as raw XML and nothing else. Forma reads the other two artifacts, a markdown spec and the `layout` that draws the in-browser mockup, off that REPX (`src/lib/repxViews.ts`, since 2026-11-05; until then the AI wrote all three in one JSON answer, and more than half of what it wrote was the two copies).

`docs/PRD.md` is the product spec and **the single copy**, kept current against the code — including its "not yet exposed in the UI" note (RTL, stored-procedure name, data-binding schema), its §5 record of the resolved key exposures, and its §6 statement that **moving generation server-side is explicitly out of scope**, not future work. If you change any of those areas, update it in the same pass.

**There is no quarantine folder, and its absence is a decision rather than an oversight.** A `_not_required/` directory existed from 2026-08-28 to 2026-08-29, holding parked files with a tracked manifest, its own `.gitignore` rules, a CI check and a pre-commit rule. It was retired: **git history is the recovery mechanism this project actually uses**, and a second one requiring three separate enforcement mechanisms was not earning its keep.

**So removals go through `git rm`, and recovery goes through `git show <commit>~1:<path>`.** Every removal site in the source carries a comment naming its commit — see `src/lib/motion.ts`, `src/components/landing/icons.tsx` and `sections.tsx`, and the `.bento-grid` note in `src/index.css`. The four files parked before the folder existed are at `9e92b86~1`, among them `metadata.json` — the AI Studio applet metadata, and the last place the pre-Forma name "DevExpress Report AI Designer" survived.

The practical consequence for a session: **if you are looking for something that used to exist and a grep finds nothing, search history before concluding it was never here.** `git log --diff-filter=D --name-only` lists every path ever deleted, and `git log -S'<symbol>'` finds the commit that removed a given piece of code.

## Structure conventions

These were already followed everywhere before they were written down on 2026-08-29, which
is exactly why they are here: an unwritten convention is one careless commit from being
broken, and nothing in the toolchain enforces any of them.

- **`src/lib` is browser code. `src/server` is not.** `server.ts` imports
  `securityHeaders`, `bindHost` and `staticCache` from `src/server/`; nothing else may.
  Before 2026-08-29 the first two sat in `src/lib`, the directory whose defining property
  is that everything in it is compiled by Vite and shipped to the browser — a component
  could have imported `resolveBindHost` and nothing would have objected. **They stay
  under `src/` rather than a root-level `server/` for one reason:** `vitest.config.ts`
  has `include: ['src/**/*.test.{ts,tsx}']`, so moving those tests out silently drops
  every case in `src/server` — `npx vitest run src/server` prints how many that is
  today (it said "forty-two" here until 2026-10-28, when the answer was 52, because
  `hostingConfig.test.ts` had arrived after the sentence). Widen that include in the
  same commit if you ever do move them.
  *Test placement* in [`docs/notes/testing.md`](docs/notes/testing.md) owns the
  arithmetic — this bullet used to state it as a before-and-after pair of suite totals,
  which was stale within days of being written.
- **File naming: `PascalCase.tsx` for React components, `camelCase.ts` for everything
